Lezione 05: Web Lab, Introspezione Neurale, Telemetria Streaming e Ottimizzazioni ad Alte Prestazioni

In questa lezione affrontiamo un doppio tema fondamentale: come aprire la scatola nera delle reti neurali attraverso un'interfaccia web di introspezione visiva in tempo reale, e come ottimizzare le prestazioni del motore di simulazione per passare da centinaia a migliaia di passi per secondo (Steps Per Second - SPS).

💡 1. L'Intuizione: La Risonanza Magnetica del Cervello dell'AI

Addestrare un modello di Reinforcement Learning guardando solo un numero nel terminale (la loss) è come cercare di diagnosticare un paziente misurandogli solo la temperatura: non vedi cosa sta accadendo negli organi interni.

Il Web Lab funziona come una risonanza magnetica interattiva (BrainView):

  • Ti mostra i neuroni che si attivano nei layer intermedi quando l'agente osserva il tabellone.
  • Evidenzia le incertezze decisionali: ad esempio, quando la policy è in bilico al 48% tra pescare carte o bloccare una tratta strategica avversaria.
  • Fornisce un Replay Scrubber per riavvolgere la partita frame-by-frame e analizzare ogni singola decisione tattica.

2. Architettura del Web Lab & Invariante Headless

Un principio ingegneristico assoluto del laboratorio è il Disaccoppiamento Headless: il motore di simulazione e gli script CLI (scripts/train.py) operano alla massima velocità hardware possibile, senza dipendenze obbligatorie dal browser o dal server web.

4. Connettività Istantanea con Disjoint Set Union (DSU)

Anziché ricalcolare una visita BFS completa ogni volta che l'ambiente deve verificare se una coppia di città $(u, v)$ è connessa, manteniamo una struttura ad insiemi disgiunti (Union-Find con Path Compression e Union by Rank):

$$\text{Find}(u) = O(\alpha(|V|)) \approx O(1)$$ $$\text{Union}(u, v) = O(\alpha(|V|)) \approx O(1)$$
💡 Perché DSU batte la BFS nella simulazione RL?

Obiettivo: Ad ogni azione di acquisto tratta, dobbiamo verificare la connettività di tutti i $30$ biglietti destinazione. Con una BFS classica, il costo per step è $O(K \cdot (|V| + |E|))$. Con la DSU, l'aggiornamento di una tratta è una singola operazione $\text{Union}(u, v)$, e ogni test di connettività è una semplice uguaglianza $\text{Find}(u) == \text{Find}(v)$.

Scomposizione dei Termini:

  • $u, v \in V$: indici interi identificativi delle città collegate dalla tratta.
  • $\text{Find}(u)$: risale l'albero fino alla radice canonica della componente connessa, collegando direttamente tutti i nodi visitati alla radice (Path Compression).
  • $\text{Union}(u, v)$: unisce gli insiemi agganciando l'albero di rango inferiore sotto la radice dell'albero di rango superiore (Union by Rank).
  • $\alpha(|V|)$: la funzione inversa di Ackermann. Per qualsiasi dimensione dell'universo conosciuto ($|V| \le 10^{80}$), $\alpha(|V|) \le 4$. L'algoritmo opera in tempo praticamente costante $O(1)$.

4.1 Throughput di Training e Legge di Amdahl

Il throughput di simulazione $SPS$ (Steps Per Second) determina il tempo di addestramento complessivo:

$$\text{SPS} = \frac{N_{\text{steps}}}{\Delta t_{\text{env}} + \Delta t_{\text{inference}} + \Delta t_{\text{train}}}$$
🔍 Scomposizione dei Tempi di Ciclo
  • $\Delta t_{\text{env}}$: tempo speso nel motore Python (logica regole, action masking, step FSM).
  • $\Delta t_{\text{inference}}$: tempo speso nel forward pass PyTorch per calcolare la policy $\pi(a|s)$.
  • $\Delta t_{\text{train}}$: tempo speso nel backward pass e aggiornamento dei pesi tramite l'ottimizzatore.
  • Principio di Amdahl: Accelerare la GPU con batch enormi non serve se $\Delta t_{\text{env}}$ domina il ciclo. Pre-allocare buffer ed eliminare le allocazioni dinamiche riduce $\Delta t_{\text{env}}$ del 70%.
💻 Implementazione del Disjoint Set Union in Python
class DisjointSetUnion:
    def __init__(self, num_nodes: int):
        self.parent = list(range(num_nodes))
        self.rank = [0] * num_nodes

    def find(self, i: int) -> int:
        """Restituisce la radice della componente con Path Compression ricorsiva."""
        if self.parent[i] == i:
            return i
        self.parent[i] = self.find(self.parent[i])  # Path compression!
        return self.parent[i]

    def union(self, i: int, j: int) -> bool:
        """Unisce due componenti con Union by Rank."""
        root_i = self.find(i)
        root_j = self.find(j)
        if root_i == root_j:
            return False  # Già connesse
        if self.rank[root_i] < self.rank[root_j]:
            self.parent[root_i] = root_j
        elif self.rank[root_i] > self.rank[root_j]:
            self.parent[root_j] = root_i
        else:
            self.parent[root_j] = root_i
            self.rank[root_i] += 1
        return True

    def is_connected(self, i: int, j: int) -> bool:
        """Query di connettività in tempo ammortizzato O(1)."""
        return self.find(i) == self.find(j)
⚠️ Le Trappole Comuni: Non Introdurre time.sleep nel Training
  • L'Errore del Falso Throttling: Rallentare il loop di addestramento inserendo sleep forzati per non sovraccaricare il frontend WebSocket rallenta inutilmente la ricerca.
  • L'Approccio Corretto: L'ambiente gira alla massima frequenza di clock. Il backend FastAPI campiona l'ultimo frame telemetrico disponibile e invia pacchetti a frequenza fissa (es. 20 FPS con intervallo di 50ms) in un thread asincrono non bloccante.

🧠 Checkpoint di Autoverifica: 5 Domande di Valutazione

Verifica le tue competenze sulle architetture di telemetria, algoritmi di DSU e ottimizzazione delle pipeline di RL.

Domanda 1 di 5: Vantaggio Prestazionale della Struttura DSU

Per quale motivo teorico la struttura Disjoint Set Union (Union-Find) con Path Compression è superiore a una ricerca in ampiezza (BFS) per verificare il completamento dei biglietti destinazione ad ogni step?

Risposta Corretta: A
Spiegazione dettagliata:
  • Perché A è corretta: Eseguire una BFS per ciascun biglietto posseduto ad ogni step ha costo $O(K(|V|+|E|))$. Con la DSU, quando una tratta viene acquistata basta una singola operazione $\text{Union}(u, v)$, e ogni test di connettività su un biglietto richiede due chiamate $\text{Find}$ in tempo quasi istantaneo $O(1)$.
  • Perché B, C e D sono errate: La DSU non trova il cammino più lungo aciclico, non è un costrutto VRAM e non governa le regole di gioco.
Domanda 2 di 5: Pre-allocazione di Array Contigui NumPy nel Replay Buffer

Perché l'uso di un array NumPy circolare pre-allocato è nettamente più performante rispetto a una lista Python o collections.deque di tuple $(s, a, r, s', d)$ nel Replay Buffer?

Risposta Corretta: A
Spiegazione dettagliata:
  • Perché A è corretta: Una lista di tuple in Python alloca centinaia di migliaia di piccoli oggetti separati. Estrarre un batch richiede di iterare sui puntatori e creare nuovi oggetti. L'array contiguo pre-allocato in C di NumPy consente il campionamento istantaneo tramite slicing vettoriale.
  • Perché B, C e D sono errate: Le liste non convertono float in testo, la convergenza della loss dipende dall'algoritmo di RL e i checkpoint su disco sono pienamente supportati.
Domanda 3 di 5: Gestione della Telemetria WebSocket ad Alto Throughput

Quando il motore di simulazione produce oltre $1500$ steps al secondo, quale strategia architetturale previene il blocco del frontend React nel browser?

Risposta Corretta: B
Spiegazione dettagliata:
  • Perché B è corretta: L'Adaptive Throttling disaccoppia la velocità di elaborazione numerica (backend a piena potenza) dalla frequenza di rendering dell'interfaccia utente (limitata a 20-30 FPS per non saturare il thread JavaScript del browser).
  • Perché A è errata: Rallentare artificialmente il training distrugge l'efficienza della pipeline.
  • Perché C e D sono errate: La telemetria deve rimanere in tempo reale e il Critic non deve essere disabilitato.
Domanda 4 di 5: Principio di Disaccoppiamento Headless

Cosa stabilisce l'invariante di disaccoppiamento Headless implementata nel laboratorio di simulazione?

Risposta Corretta: A
Spiegazione dettagliata:
  • Perché A è corretta: L'esecuzione headless assicura che il core matematico e gli script di benchmark/training su cluster o terminale non abbiano dipendenze bloccanti da server web, browser o interfacce grafiche.
  • Perché B, C e D sono errate: Headless significa "senza interfaccia grafica utente", non rimozione di layer della rete neurale né dipendenza forzata da browser.
Domanda 5 di 5: Significato della Funzione Inversa di Ackermann $\alpha(N)$

Nel contesto della complessità temporale della DSU con Path Compression e Union by Rank, cosa comporta che $\alpha(|V|) \le 4$ per ogni valore pratico di nodi?

Risposta Corretta: A
Spiegazione dettagliata:
  • Perché A è corretta: La funzione inversa di Ackermann $\alpha(n)$ cresce così lentamente che per qualsiasi dimensione realistica (anche superiore al numero di atomi dell'universo), il suo valore non supera mai $4$. In termini pratici, la DSU ha complessità costante $O(1)$.
  • Perché B, C e D sono errate: $\alpha$ è una funzione di complessità asintotica e non limita il numero di città, i tempi fisici o l'occupazione di memoria della mappa.
